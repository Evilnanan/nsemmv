# PC 存档格式与证据

仅支持角色数据版本 308。实现把容器、角色记录、库存、配装和规则分开；读取不规范化已有数据。这里区分原生指令证据、样本验证和尚未完全确认的部分。

## 输入身份

原生核对使用 PC `nightreign.exe` 1.3.3.0，ImageBase `0x140000000`，SHA-256：

`9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`

下文地址均为 RVA，不可套用到其它 EXE。仓库不分发游戏代码或个人存档。`tools/audit_native_serializers.py` 提供只读指令检查；`tools/native_mutation_probe.py` 使用本地 EXE 和 Unicorn，对合成对象运行有限的初始化、预设创建及删除函数。UTF-16 复制被等价桩替换，删除后的排序调用被观察并跳过，排序规则另由比较器确认；这不是完整游戏运行。

## 容器与角色区

BND4 区段各自保存 IV、AES-CBC 密文和内部 MD5。解析验证区段范围、不重叠、加密块长度和校验和；无修改时返回原始文件。修改时只重加密变动角色，导出后重新解密核对。其它区段和容器尾部保留。

角色槽占用信息在全局区段中定位，当前采用唯一 `FACE` 结构与其前方占用数组的样本规则；候选不唯一则拒绝。角色名称与库存相对位置已用真实存档验证，但尚无完整 PlayerGameData 字段模型。

## 遗物状态、抽取与入库

| 原生函数 | 已确认行为 |
| --- | --- |
| `0x69f560` | 保存 5120 个物品状态槽。空槽为 8 字节；遗物槽为 8 字节实例前缀加 72 字节主体 |
| `0x69e940`、`0x69e90a` | 当前版本遗物主体写入、读取长度均为 72 字节 |
| `0x6c0c10` | 主体默认初始化，词条和若干保留槽为 `FFFFFFFF`，不是全零 |
| `0xe6c7e0` | 从正面池抽取并检查兼容性，深层再抽对应负面池；正负词条使用同一个排序排列 |
| `0x69fce0` | 从空闲状态队列分配实例，然后初始化、抽取并填入主体 |
| `0x6c19b0`、`0x6c1990` | handle 使用低 16 位状态索引、7 位代次和 live 位 |
| `0x69f820` | 载入引用时拒绝超过 5119 的旧状态索引，再通过映射解析实例 |
| `0x754470`、`0x755040` | 库存由 2688 个主条目和 384 个关键物品条目构成，两区各有一个数量字段 |
| `0x754350`、`0x7541c0` | 序列化条目长 14 字节：handle、数量、获取序号、收藏、new 标记 |
| `0x1f6780` | 两区后另保存最大库存索引和下一个获取序号 |
| `0x1f6de0`、`0x1f62a0` | 遗物进入主库存；写数量、获取序号并推进元数据 |
| `0x754410`、`0x754180` | 新条目的实例、新获取标记和数量/序号初始化 |

创建使用空闲状态索引，不把不断增长的获取序号当作 handle 索引；同时避开原有 handle 的低位索引。写入主库存、数量 1、收藏 0、new 1，并更新该区数量及获取元数据。关键物品区不会被当作备用遗物容量。原有数量不一致在读取时保留，实际增删时仅更新对应区。

handle 索引越界是原生加载器可以明确拒绝的条件；并不能据此断言所有“游戏里看不到”的反馈都出于同一原因。当前验证包含静态调用链、隔离原生函数和存档回读，尚未完成真实游戏内领取/加载验收。

## 预设

原生 `0x1dfca0` 写入 `0x000300c2` 配装块，`0x1e14a0` 序列化 10 个角色、70 个角色专用器皿、4 个通用器皿及 100 个 80 字节预设槽。解析以完整器皿、角色、引用结构交叉验证位置，不把活跃预设压缩成连续索引。

- `0x1e0010` 创建：占用标记、角色、器皿、六个引用、FILETIME；新预设排序计数为 0，原有计数递增。
- `0x1dff30` 重命名：仅修改名称，保留时间戳与排序信息。名称为最多 18 个 UTF-16 码元，允许中文与其它 Unicode；不允许内嵌 NUL。
- `0x1dfeb0` 删除：清占用、角色、器皿、六个引用和时间戳，保留旧名称及保留字节。
- `0x1e17a0` / `0x1df1b0`：按计数升序、时间戳降序整理排序计数，不移动物理槽位。
- `0x1e1b10`：依据器皿及六个遗物匹配当前预设，选择计数最小者。
- `0x1dfdc0` / `0x1dfe00` / `0x1dfe60`：装备更新器皿内容、当前器皿和物理预设索引。

内容替换采用清除并重建该物理槽位，单独改名不重建。遗物若仍被器皿或预设引用则不允许删除。器皿需要已持有且颜色、普通/深层槽型匹配。

## 名称显示与存储

PC 字体查找 `13BF850` 在查字形前将七种 UTF-16 字符替换为显示字符：`⑲ → #`、`⑳ → ?`、`㉑ → <`、`㉒ → >`、`㉓ → %`、`㉔ → ＼`（全角反斜杠）、`㉕ → ¥`。角色名、预设名读取时按此映射显示。不是 HTML 实体，也不对其他 Unicode 字符做兼容归一化。

`tools/probe_name_glyphs.py` 在固定版本 EXE 的原生指令中遍历全部 65536 个 UTF-16 码元，停在字形表读取前；结果见 `data/name-glyph-evidence.json`。这里只验证字形选择，不声称运行了游戏界面。当前目录及提取的中英文 FMG 名称／说明没有这七种编码；网页本身没有其他全局符号替换。

显示转换不写回存档。未改名的预设在修改配装时也保留名称原字节，兼容已有的字面符号和专用编码混用。新增／改名时使用与显示字符对应的游戏字体编码，仍按原有 UTF-16 长度限制。ASCII 反斜杠、全角尖括号、其他圈号、中文和代理对均不额外替换。

## 未解明边界

配装区外仍有未建模的状态、领取历史和事件标记。本工具不模拟完整奖励事件、购买条件、剧情解锁或运行时 UI 刷新。角色流使用固定容量；遗物状态增删会使后续流平移 72 字节，并消耗/补回尾部容量。尾部按当前样本表现作为分配器余量处理，尚未从完整原生根序列化器证明每个未知尾字节的含义。因此，结构编辑不承诺所有未知尾字节保持原位或往返完全一致；撤销和原始备份保持完整原字节。已有遗物原位编辑及无修改导出不需要平移。

未知布局禁用依赖配装引用的结构修改；不同游戏数据版本拒绝解析。浏览器离开提醒使用浏览器原生对话框，不能自定义为桌面程序的“保存/不保存/取消”，也不能保证移动系统强制杀进程时触发。
