# 词条生效机制研究

本轮覆盖当前 MMV 中 885 个可获取遗物定义涉及的 **637 个不同词条**，包括商店遗物。完整逐条记录见 [`data/effect-research.json`](../../data/effect-research.json)：每个词条都有根效果、状态类型、已展示数值的来源、叠加证据和待解问题。目录中的其它能力保留基础详情，但不计入这 637 个遗物词条。

| 当前进度 | 数量 |
| --- | ---: |
| 已建研究记录 | 637 |
| 有可展示的字段或替换法术 | 447 |
| 其中有已解读的数值字段 | 432 |
| 其中仅有替换法术名称 | 15 |
| 已核对原生叠加处理 | 231 |
| 尚未解析到可展示字段 | 190 |

这些是不同维度的覆盖数，不能相加作为“完全解明”数量。`decoded-fields` 只表示解读了数值字段；`native-analysis` 表示当前代码处理已核对，不表示完成了整局、多人或所有边界的游戏实测。没有完成游戏实测的条目统一保留 `gameplayVerified: false`。研究记录不进入主界面。

## 固定输入与复现

- MMV：Daybreak 2.1.9 Beta2-Release，regulation `10350000`。
- regulation SHA-256：`3305ac374b4da1db440e2b6644bc2c3c0ae96b98df9627f1a0e7a2b06d265c06`。
- PC EXE：1.3.3.0，SHA-256 `9545e8732919bb6a63904cb73223641b3c4f9a67869be5722612acca413e8b3a`，以下均为 RVA。

仓库只保存必要派生数据及验证输出，不保存游戏程序、完整 PARAM 或个人存档。提取时使用 Smithbox 的当前版本定义，过滤不适用于 `10350000` 的字段。输出后重新读取 JSON；`--research` 另外导出实际 PARAM 字节和 common EMEVD 指令，供本地只读分析。

```sh

dotnet tools/ExtractEffectDetails/bin/Debug/net10.0/ExtractEffectDetails.dll <Smithbox目录> <游戏目录> <MMV的mod目录> <临时目录>/extracted.json --research
```

## 原生执行检查

[`probe_effect_mechanics.py`](../../tools/probe_effect_mechanics.py) 在 Unicorn 内执行原 EXE 的指令，使用实际 MMV 的 1024 字节 SpEffect 行、28 字节 HeroStatus 行，构造效果链表和有效/无效节点。字段偏移先与提取器解码结果逐行核对。遇到未准备的依赖或超过执行预算即失败。

共 **748 组检查**：9 组匹配谓词、10 组能力值、36 组攻击倍率、3 组承伤倍率、8 组冷却、5 组发现倾向、24 组绝招累积、400 组角色等级调整、98 组抵抗力、32 组 FP 消耗、6 组技艺次数、4 组杀敌回绝招等级匹配、24 组杀敌分派、5 组绝招百分比结算、21 组恢复计时、63 组受损异常触发及积累量。结果保存为 [`effect-native-evidence.json`](../../data/effect-native-evidence.json)。

外部依赖替代包括：`E6D630` 无武器 PARAM 的查询，`E78730` 用实际 HeroStatus 字节实现的表查询，`E78720` 表包装对象清理；杀敌分派的 `3C7FD0` 记录下游效果 ID，随后单独执行真实数值聚合；绝招结算中的 `42C120/3D4180` 提供无玩家 HUD 通知的合成 owner；计时刷新中的 `EA17E0` 查询实际 SpEffect 行。完整清单保存在输出的 `stubs`。倍率、实例匹配、等级选择、插值、取整、计时、累计值重置均执行原生代码。没有启动游戏进程，没有模拟完整远征。

## 已确认的处理

### equip-injection / instance-matching

`E6E3B0` 读取 Attach 的三个被动效果。`4FF520` 收集各项被动效果，`4FF2E0` 逐项派发；`4FEA30` 另处理装备时的 exclusivity 与角色允许条件。因此只对根节点简单、没有额外触发链或状态条件、没有装备 exclusivity 限制的类别 10 / 状态 0 词条发布通用叠加结论。

效果添加路径 `50D060` 调用 `510B20`、`510B70`、`510BD0` 和 `511450`。已检查的类别 10 不因相同 ID 复用现有节点；类别 20 会复用相同 ID。不能将这个结论扩大到所有类别，亦不能只从词条名字或菜单筛选标志推导叠加方式。

### attributes / attack / defense / cooldown

- `502300`：八项能力值增减相加，包括重复与不同等级。
- `502830`：已生效且通过攻击过滤的五通道 AttackRate 相乘。来源类型 3、4 是魔法、祷告通道；三份“强化魔法和祷告＋２”得到 `1.14³ = 1.481544`。属性攻击与法术强化可同时进入相乘路径。
- `503800`：承伤倍率相乘。三份魔力承伤 `0.84` 得到 `0.592704`。
- `508480`：有效节点的技艺冷却时间倍率相乘，带最终限幅；不是将“缩短百分比”直接相加。
- `511010` 的攻击分类过滤和相关 PARAM 同时约束增攻。分类 103 是防御反击，130 是近战；不能把所有类别字段都显示成“指定法术类别”。魔法与祷告适用标志也不替代分类判定。

### weapon-count / discovery

三武器条件词条为状态 2100、类别 20；`wepTypeTriggerCount` 为 3。同一种效果重复使用会复用节点，不再获得第二份数值。不同种类的效果在各自条件成立时分别生效。原生攻击计算中同时放入三弓与三短剑的有效节点，倍率为 `1.2 × 1.2 = 1.44`；这项隔离检查不模拟换武器动作。

`5072D0` 返回有效链表中遇到的第一个状态 2122 的 `weaponTypeDiscovery`。弓/手杖顺序互换时返回类型随之变化。详情归为“不可叠加”，并写明“采用生效列表中的第一个”，不声称界面左边的遗物必定优先，也不把多个倾向解释为各自独立增加概率。

### gauge

- `508BE0` 汇总 `ultimateArtGaugeRate`；`48BEF5` 的调用点位于按时间推进的自然增长循环。
- `508B90` 汇总 `ultimateArtGaugeChargeRate`，额外要求节点标志 4；`6CC0DC` 的攻击结算调用点使用该结果。
- `508C70` 的周期效果增长也读取 ChargeRate，对正向增长应用倍率。

“自然累积绝招量表＋１”实际两个字段都是 1.05；“降低绝招量表累积”均为 0.85。两个通道分别相乘，不能把它们相乘后称为一次增长的总倍率，也不能把 ChargeRate 标成自然增长。

“降低绝招量表累积”（6840200）也降低杀敌回绝招的恢复量。`508C70` 在汇总杀敌子效果的正向增长后，乘以有效节点的 `ultimateArtGaugeChargeRate` 乘积（`508D48`），再交给百分比结算。因此每条乘 0.85，两条乘 0.7225。使用实际参数执行该函数，覆盖普通版、＋１版、两版同时存在的两种分支，各搭配 0～3 条负面，共 24 组；两版合计的 3.8%／11.5% 在两条负面下变为 2.7455%／8.30875%。此处验证的是原生数值计算，未运行游戏进程。

进一步核对所有累积入口：自然累积为 `48BEF5 → 508BE0`；攻击为 `43E2DB → 6CC030 → 508B90`，先应用倍率再由 `43E2E6 → 48BB90` 加入点数；效果恢复为 `6714D8 → 508C70`，百分比与固定点数均先应用倍率，再分别交给 `48BC60`／`48BB90`。后两种加量函数的直接调用者均已核对。当前参数中全部 22 个正向 `ultimateArtGauge` 行，各搭配 0～3 条负面，88 组隔离执行均符合 ×0.85ⁿ。

例外为训练场直接补满：`48BDB0` 将当前量表写为最大值，不读取累积倍率；直接调用者 `1FC470` 管理训练选项（103530～103580），由 `903ED0` 转发。`903E50` 构造对象的虚表 `2C49E58` 对应 RTTI `TrainingAreaViewModel@CS`，确认其训练场来源。该操作不属于出击中的累积。详情按出击中的累积合并描述所有来源，不列训练场设置；不将角色初始化、存档恢复视为累积。

### hero

状态 2123 由 `501D30` 遍历并调用 `6C8A60`，根据 `heroStatusModifier` 读取连续的 HeroStatus 行。按 `totalLevel` 选择左右端点，中间等级交给 `6C2390` 线性插值，以单精度运算，最后 `cvttss2si` 向零取整；超出最后端点沿用最后一行。

全部 20 类调整均执行 1～20 级，共 400 次。例：“【隐士】提升智力、信仰，但降低集中力”：1 级为集中力 -2、智力 +2、信仰 +2；2 级为 -3、+2、+2；12 级起为 -13、+12、+12。详情合并数值相同的连续等级，保留未知的跨遗物重复规则。

## 叠加分类与新增结论

浏览器 `stacking` 只使用“不可叠加”“可叠加”“不同等级可叠加”；证据不足为“待确认”。`stackingDetail` 单独说明相加、相乘、不同类型同时生效等细节。分类只来自当前参数与原生代码证据，不以使用报告作为依据。

### resistance / fpCost / skillUses

`507DE0 → 5107D0 → EA0DC0` 对七种抵抗力逐节点相加。普通抗毒 +75 与 +1 的 +110 合计 +185；正负词条也按点数相加。

FP 消耗倍率分别由 `507310`（魔法）、`5081E0`（祷告）、`507410`（特殊法术）、`5061B0`（战技）相乘。三份 +2 版得到 `0.84³ = 0.592704`，不是将节省百分比相加。

`5059B0` 汇总技艺使用次数，但追踪者/铁之眼 +1 的根效果是类别 20，同 ID 会复用一个节点，所以同一词条重复装备归为“不可叠加”。

### killMatching / killDispatch / gaugeApply

普通版 `7090000 → 7090000`，+1 版 `6090000 → 7090010`。两种根效果均为类别 20、状态 199，没有装备 exclusivity 限制。原生 `510B20/511450` 对四种同/异 ID 配对确认：同等级复用，不同等级各保留一个。

`50A150` 遍历有效状态 199 的节点，每个节点选择一条分支，调用 `3C7FD0`。布尔值为真且 KillSp 有效时选 KillSp，否则选 GetSoul。不能根据这两个旧字段名称认定是“本人补刀/队友补刀”：`3DE7E2` 的直接调用路径读取敌人 NpcParam `+0x26A` 的 bit 2（当前定义 `enableSpKillId`），通过 `668380` 传入；奖励恢复路径 `51DC0B` 还携带保存的标记。

| 分支标记 | 普通版子效果 | +1 子效果 | 两版合计 |
| --- | --- | --- | --- |
| 0 | 7090001：5% | 7090011：6.5% | 11.5% |
| 1 | 7090002：1.65% | 7090012：2.15% | 3.8% |

`508C70` 相加两个子效果的 `ultimateArtGauge`；`6714D8 → 48BC60` 将结果乘 0.01 和最大量表，并限幅到最大值。隔离执行使用最大量表 1000，5 对应增加 50，11.5 对应增加 115。因此详情使用百分比，并归为“不同等级可叠加”；同等级重复无效。未确认敌人分类名单时显示两种可能值，不将两分支之和当作一次击杀的收益。

### damage-status

6820000～6820600 的根效果使用 `deleteCriteriaDamage=12`，受损后替换为 `root+1`，该节点周期发出 `root+2` 并返回根效果。`43CBB6 → 504D30` 仅以损伤数值是否大于零及来源标记判断是否将根节点寿命置零，不按损伤大小缩放积累量。隔离执行每个根效果的 0、1、100、10000 损伤与两种来源标记，共 56 组，确认此门控。没有把这项检查解释为完整防御、自伤、多段攻击或联机场景测试。

异常应用路径 `3DB4E7 → 42D110` 按状态读取对应的 `*AttackPower`，经 `EA0D20 → 42E0E0` 计算，向零取整后由 `42CD70` 扣减剩余异常耐受量。无额外积累修正时，中毒为 52 点，腐败／冻伤／出血各 44 点，发狂／催眠各 40 点，死亡为 32 点。7 组检查执行真实读取、默认修正计算及低于发作阈值的量表写入；量表初值 1000，分别剩余 948／956／960／968。免疫、其他积累修正、异常发作与根节点完整重建未在该隔离环境模拟。

详情按每次受损触发显示固定积累点数，不将 `root+2` 中异常发作后的 HP／FP 损失、减防与持续时间当作每次受损立即发生的效果。临时节点的 0.1 秒也不标为异常持续时间。同词条多份的完整触发时序仍待确认。

### recovery-timing

一次性恢复不能直接展示 SpEffect 的存活时间。`511B80` 在周期计时到期时调用 `511D20` 标记一次结算，`507460` 等资源汇总函数只消费当次有效标记。`5113F0` 判断到期，`511700` 刷新存活时间但不会在普通刷新路径重置周期，也不会立即制造新一次结算。

21 组计时检查以 60 Hz 推进真实原生函数，覆盖单次触发、0.2 秒后重复触发，以及每 0.2 秒刷新并持续 6 秒，并对原始全行字段进行中性字段比对，将 **73 个仅含恢复及已核对附带机制的节点**匹配到已测计时类型。效果结束替换、额外条件或混合增益不自动套用此规则。

- 连续攻击回 FP 的 `7036001` 存活 1 秒、周期 4 秒，在未刷新时只恢复一次。首次结算通过 `511D20 → 50DB20 → 50E240` 将累计值减少 999 并限幅到 0；随后新增的累计值 7 在剩余存活期间保留，不会持续清零。因此隐藏“持续 1 秒”，说明“恢复时重置连续攻击累计进度”。
- 短剑攻击回 FP 的 `8600211` 存活 1 秒、周期 1.1 秒，同 ID 复用。首次触发恢复 2 FP；0.2 秒后刷新不立即再次恢复，但延长后的节点可在约 1.1 秒结算第二次。详情隐藏误导性的持续标签，明确重复触发刷新与再次结算间隔。0.3/0.4 秒的命中恢复族按相同方式说明。
- 连续腐败回血的 `7260901` 是 15 秒、1.3 秒间隔的持续恢复，保留持续时间和周期；混合魔法的 3 秒增益也保留。带额外条件的受损回 FP 等节点不因外观相似而直接归类。

以上是节点计时及结算机制验证；攻击触发资格、多人、重载等未覆盖问题仍在逐条记录中保留。

## 已解读字段及尚未完成的链

### action-triggers / triggerMatching / extraGetters（全目录研究第一批）

`ExtractEffectTriggers` 读取实际加载的 `chr/c0000.anibnd.dcx`，SHA256 为 `1410035ad79edb410fa41420ec259fcb4a1037d748c9c4a3b6ae8d1366c76d0f`。从标准动画的 66/67/401 事件读取 SpEffect ID，逐项核对其状态条件对应遗物根状态。只提交已复核的 20 个根标记、相关事件参数和资产哈希；完整动画不入库。`c0000_a6x.anibnd.dcx` 没有 TAE，不从它猜测触发。新增等级同样必须找到实际动画引用。

接通苔药回血、防御回大、致命回大、致命加精力恢复、油脂加攻、无赖技艺受击增益、追踪者能力增益、铁之眼绝招突刺反击、发狂回 FP、换武器加攻和防御回血。动作发放的是条件子节点，不按根标记的装备份数重复发放；40 组 `510B20/511450` 检查确认数值叶节点的类别 20 按 ID 复用，不同等级 ID 独立。发狂回 FP 的两个同名变体保留叠加待确认，不擅自称为普通版／＋１版。

- 致命后的精力恢复速度为 +10／+17／+20，15 秒。`505AA0` 逐节点相加，三档为 +47；`4DACD0/66CAA0` 将它加入基础恢复速度。未完成后续每帧积分单位追踪，不把它改写成百分比或每秒数值。
- 防御回血 `7036102` 是 +15 HP，状态 2308 对应持有根效果。条件成立时归入已验证恢复计时族：首次恢复，1 秒内重施只刷新寿命，持续刷新约每 1.1 秒恢复一次。新增两组实际计时执行，恢复行审核由 73 扩展到 74；不展示内部 1 秒为增益时长。
- 商店折扣 `7230000/7230001` 的状态 2116 由 `508280` 计算 `(1-10%) × (1-20%) = 72%`，调用者 `869840` 将结果用于商店价格流程。相同 ID 在 `510B20` 复用；类别 0 不经过类别 20 的匹配分支，单独检查，不套用类别 20 的假设。价格最终整数取整不在本批结论范围。
