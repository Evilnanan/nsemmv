# 词条生效机制研究

本轮覆盖当前 MMV 中 885 个可获取遗物定义涉及的 **637 个不同词条**，包括商店遗物。完整逐条记录见 [`data/effect-research.json`](../../data/effect-research.json)：每个词条都有根效果、状态类型、已展示数值的来源、叠加证据和待解问题。目录中的其它能力保留基础详情，但不计入这 637 个遗物词条。

| 当前进度 | 数量 |
| --- | ---: |
| 已建研究记录（完整目录／可获取范围） | 2241／637 |
| 有可展示的数值、机制或替换法术 | 565 |
| 其中有已解读的数值字段 | 494 |
| 其中仅有替换法术名称 | 35 |
| 其中仅有机制说明 | 36 |
| 已核对原生叠加处理 | 283 |
| 尚未解析到可展示详情 | 72 |

这些是不同维度的覆盖数，不能相加作为“完全解明”数量。`decoded-fields` 只表示解读了数值字段；`decoded-mechanism` 单独记录不含新数值的机制说明；`native-analysis` 表示当前代码处理已核对，不表示完成了整局、多人或所有边界的游戏实测。没有完成游戏实测的条目统一保留 `gameplayVerified: false`。研究记录不进入主界面。

## 原生执行检查

[`probe_effect_mechanics.py`](../../tools/probe_effect_mechanics.py) 在 Unicorn 内执行原 EXE 的指令，使用实际 MMV 的 1024 字节 SpEffect 行、28 字节 HeroStatus 行，构造效果链表和有效/无效节点。字段偏移先与提取器解码结果逐行核对。遇到未准备的依赖或超过执行预算即失败。

目前主验证文件有 **1728 组原生检查**，武器倾向另有 **2020 组**（394 组倾向选择、1626 组抽选），图腾 **86 组**、完整效果链 **56 组**、守护者回血 **22 组**，另有 **244 组实际 HKS 分支检查**。原生结果按谓词、能力值、倍率、计时、触发、成长等分别记录，不把记录数当成已解明词条数。

外部依赖替代包括：`E6D630` 无攻击（AtkParam）行的查询，`E78730` 用实际 HeroStatus 字节实现的表查询，`E78720` 表包装对象清理；杀敌分派的 `3C7FD0` 记录下游效果 ID，随后单独执行真实数值聚合；绝招结算中的 `42C120/3D4180` 提供无玩家 HUD 通知的合成 owner；计时刷新中的 `EA17E0` 查询实际 SpEffect 行。完整清单保存在输出的 `stubs`。倍率、实例匹配、等级选择、插值、取整、计时、累计值重置均执行原生代码。没有启动游戏进程，没有模拟完整远征。

## 已确认的处理

### 武器发现倾向（第五批）

覆盖 6630000～6633600 共 37 个目录词条，其中 36 个属于当前可获取范围。`56ACF0` 先读取 HeroParam 的 `defaultWeaponTypeDiscovery`（行 1～10 分别为 1100～2000），再调用 `5072D0` 读取首个状态 2122 的 `weaponTypeDiscovery`。有遗物时直接替换默认值，不相加；弓与手杖的节点顺序交换后结果随之交换，同种重复仍为一份。394 组完整 `56ACF0` 执行覆盖 10 个角色、37 种词条、缺少 owner／无词条以及重复和混合顺序；HeroParam 查询替代使用真实行字节，SpEffect getter 未替代。生效列表顺序没有绑定到编辑器界面的遗物位置。

**重复行是抽选结构的一部分。** ItemTableParam 的同一 ID 表示一个候选组，当前数据有 35755 行、3627 个组。旧研究提取器的 ID 字典会留下每组最后一行；本次新增 `--discovery`，以 `orderedTables.ItemTableParam` 保留顺序及全部重复行。其它表的唯一 ID 仍放入 `tables`；重复 ID 的所有版本连同行序号放入 `orderedTables`，从唯一字典移除，防止后续查询静默选取其中一行。完整研究提取另检出 AtkParam_Pc 的 600000535 有两个不同版本；当前已发布效果链不引用它，其原生取行规则留待研究。当前数值详情没有使用此前被折叠的 ItemTable，因此不回填未经验证的历史概率。原生探针将全部 35755 行的关键字段逐项与实际 PARAM 字节核对。

奖励路径 `5769D0 / 581B20 → 56ACF0 → 56ABB0 → 568320 / 569330` 将倾向值传给 `E79680`；嵌套 ItemTable 经 `56AF10` 继续传递。`E79680` 在保留角色、事件及去重条件后，允许 `weaponTypeDiscovery = -1` 的通用候选和与当前倾向相等的候选；累加 `chanceWeight`，用随机数选择累计区间。倾向不是全局概率加成，也不改写候选本身的权重。未设置倾向条件的奖池不受影响。

1626 组完整 `E79680` 执行覆盖全部 39 个带倾向条件的参数组与 37 种武器倾向、隐士默认值 1700 及无倾向输入；另检查 10 个角色、随机区间首尾、通用奖池、事件门槛和重复候选排除。PARAM 行读取、条件判断、累计权重和随机区间选择均执行原 EXE；只替代内存分配、随机数输入、旗标状态及缺失运行时对象。代表性边界：3000250 没有调香瓶候选时返回 -1；2003002 的通用候选总权重始终 21000；2000 的角色／旗标门槛不会被武器倾向绕过。上层遇到 -1 如何处理仍未完成，不把它解释成最终无奖励或自动回退。

详情只展示武器种类、替换默认倾向、适用奖励范围、权重影响与不可叠加，不发布未经入口验证的固定掉率。研究记录新增 `decoded-mechanism`，故可获取范围增加 36 个有详情，数值已解读数仍为 480。参数组的存在不证明每个远征奖励入口都会调用它；完整外层概率、MMV 新武器的入口可达性及上层回退仍待追踪。

**特殊地点攻击成长（7060000 及同根条目）。** 绑定当前 common 事件 0 的 393～397 初始化与 1400/1402/1407/1408/1409 的参数化指令，确认两组独立类别 204 梯级：7069001 起每档约 ×1.05，7069021 起每档约 ×1.015。PARAM 存在小数取舍，因此不声称各档精确等于幂公式。前组从监牢最多发放 3 档、入侵者 2 档、魔法师塔事件 1 档；后组据点事件最多 8 档，拟态敌人事件连续发 2 档，共用 10 档梯级。20 档各自及两组共存的攻击 getter 共 21 组确认倍率相乘。

### weapon-count / discovery

三武器条件词条为状态 2100、类别 20；`wepTypeTriggerCount` 为 3。同一种效果重复使用会复用节点，不再获得第二份数值。不同种类的效果在各自条件成立时分别生效。原生攻击计算中同时放入三弓与三短剑的有效节点，倍率为 `1.2 × 1.2 = 1.44`；这项隔离检查不模拟换武器动作。

`5072D0` 返回有效链表中遇到的第一个状态 2122 的 `weaponTypeDiscovery`。弓/手杖顺序互换时返回类型随之变化。详情归为“不可叠加”，并写明“采用生效列表中的第一个”，不声称界面左边的遗物必定优先，也不把多个倾向解释为各自独立增加概率。

### gauge

- `508BE0` 汇总 `ultimateArtGaugeRate`；`48BEF5` 的调用点位于按时间推进的自然增长循环。
- `508B90` 汇总 `ultimateArtGaugeChargeRate`，额外要求节点标志 4；`6CC0DC` 的攻击结算调用点使用该结果。
- `508C70` 的周期效果增长也读取 ChargeRate，对正向增长应用倍率。

“自然累积绝招量表＋１”实际两个字段都是 1.05；“降低绝招量表累积”均为 0.85。两个通道分别相乘，不能把它们相乘后称为一次增长的总倍率，也不能把 ChargeRate 标成自然增长。

“降低绝招量表累积”（6840200）也降低杀敌回绝招的恢复量。`508C70` 在汇总杀敌子效果的正向增长后，乘以有效节点的 `ultimateArtGaugeChargeRate` 乘积（`508D48`），再交给百分比结算。因此每条乘 0.85，两条乘 0.7225。使用实际参数执行该函数，覆盖普通版、＋１版、两版同时存在的两种分支，各搭配 0～3 条负面，共 24 组；两版合计的 3.8%／11.5% 在两条负面下变为 2.7455%／8.30875%。此处验证的是原生数值计算，未运行游戏进程。

进一步核对所有累积入口：自然累积为 `48BEF5 → 508BE0`；攻击为 `43E2DB → 6CC030 → 508B90`，先应用倍率再由 `43E2E6 → 48BB90` 加入点数；效果恢复为 `6714D8 → 508C70`，百分比与固定点数均先应用倍率，再分别交给 `48BC60`／`48BB90`。后两种加量函数的直接调用者均已核对。当前参数中全部 22 个正向 `ultimateArtGauge` 行，各搭配 0～3 条负面，88 组隔离执行均符合 ×0.85ⁿ。
