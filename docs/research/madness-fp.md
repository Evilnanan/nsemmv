# 发狂后持续恢复专注值

7035500、7035510 在**自身发狂受创动作**开始后获得 25 秒回蓝：开始时恢复 1 FP，之后约每 0.5 秒恢复 1 FP。同一版本重复装备不增加恢复量；两个同名版本可以同时生效，每次合计恢复 2 FP。再次触发刷新持续时间，保持原有恢复节奏。跳过发狂受创动作时不会触发。

两个版本在当前文本中名称完全相同，没有一个标为“＋１”。界面使用“可叠加”，并明确限定为两个不同版本，避免把重复装备同一版本误读为叠加。

[原生探针](../../tools/probe_madness_fp.py)与[证据](../../data/effect-madness-fp-evidence.json)固定当前 PC EXE、MMV regulation、原始 PARAM、HKS、行为图及 TAE。`gameplayVerified=false`，没有运行完整游戏。原始游戏资料只读。

## 自身动作触发

HKS 的 `ExecDamage` 在 `GetDamageSpecialAttribute(STATUS_EFFECT_MADNESS)` 为真时请求 `W_DamageMad`。原函数在此之前有多个返回分支，例如 `IsDamageMotionOff`、102551 和学者技艺 708050 的受击处理。探针在 Lua 5.4 中执行原始提取函数，显式提供环境查询和辅助函数，确认普通发狂请求该动作，而六组输入中的五个提前返回对照不会请求。Lua 5.4 验证只代表这段脚本在列明输入下的分支，不等于执行游戏的 HKS VM，也不代替全部受击调度。

固定行为图中，`DamageMad` 状态经 `DamageMad_CMSG` 指向 `a000_005850`。所有引用都通过原始 ITEM／PTCH 校验读取，不根据名称猜测动画编号。TAE2000 的动画 5850 在 0～0.1 秒含两个 Type 67 事件，分别发放 7035501、7035511。原生 `27D0F10 → 27D0400` 重定位、遍历并取得真实事件载荷，再经 `410CA0 → 40FF20 → 3C8BE0 → 3C80A0` 发放给事件所属角色。

两条装备根分别为状态 2279、2376。两个零寿命标记以对应装备状态为条件，周期分支发放各自的恢复效果 7035502、7035512；未装备相应词条时，该事件不产生恢复增益。仅有装备根也不会自行开始回蓝。这条路径与“附近人物发狂增攻”的弹体通知不同，不能把附近敌人发狂的范围条件套到本词条。

## 数值、时间与叠加

两个恢复行除装备条件状态外，解码字段相同：类别 20，25 秒，周期 0.5 秒，`changeMpPoint=-1`、`changeMpRate=0`。实际装备选择允许两个根同时存在。原生容器对同一恢复 ID 去重，不同恢复 ID 分别计算，FP 消费者 `507460` 将恢复量相加。

最大 FP 为 1／99／1000／2345 时，单个版本每次都产生 `[1, 0]` 的恢复包，不按最大值缩放。两个版本为 `[2, 0]`；同版 1／3 份的结果一致。停用对照保留原本的应恢复标志，再叠加停用位，结果归零，避免因为直接清掉周期标志得到无意义的零值。

30／60／120 Hz 的原生时间线都在增益首次生效时产生一次恢复包，之后约每 0.5 秒产生一次。受测未刷新时间线各产生 51 次恢复包。此计数属于显式调度下的 FP 包结果，尚未执行最终当前 FP 写入和上限处理，因此页面只展示周期与时长。

相隔 1 秒或 5 秒的新发狂动作刷新 25 秒寿命，不重新开始回蓝周期，也不会额外立即恢复一次。两个版本分别刷新自己的恢复效果。连续帧重复发放同一动画事件不会每帧重新触发；单次标记到达对照中，相隔 1 帧仍是同一轮标记，而 0.1 秒、1 秒、5 秒后重新到达可再次发放。这不是 1 秒全局冷却：标记的周期参数不能直接作为玩家冷却时间。

“延长魔法、祷告的有效时间”的两个受测版本不改变这 25 秒。与“持续恢复专注值＋２”在 0／1／3 份组合中，完整 FP 包逐帧等于各来源独立运行结果相加；不同来源保留各自恢复时机。

## 移除与边界

225 项原生分组检查：装备选择 66、原始事件 2、分发 54、恢复量 36、完整寿命 12、动作刷新 6、标记再次到达 5、移除根 3、时长延长对照 6、停用 8、持续回蓝组合 27；另有 6 项隔离 Lua 脚本检查。

仅在原生容器中移除某个装备根，会使其恢复行失去资格，停止回蓝并暂停剩余寿命；另一个版本继续运行。原地重新加入根可使保留的恢复行重新获得资格。真实换装可能另有完整效果清理，所以不把该隔离结果写成“换装后还能续用”的玩家机制。

未执行完整异常发作到动作调度、所有动作跳过／中断组合、全部 HKS VM／Havok 状态运行、最终当前 FP 写入／上限／溢出、DLL 改写、完整装备清理重建、死亡／重载和多人同步。保留这些边界，不因数值和叠加已验证就宣称完整实机验证。

运行需要原生探针使用的 Unicorn、pefile，以及系统 `liblua5.4`。

```sh
python tools/probe_madness_fp.py <EXE> <extracted.json> <animations.json> <behavior.json> <c0000.hks> data/effect-madness-fp-evidence.json
```
