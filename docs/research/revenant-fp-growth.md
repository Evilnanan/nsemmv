# 复仇者：发动能力时提升专注值上限（部分解明）

对象：AttachEffect `6500500`，Daybreak 2.1.9 Beta2-Hotfix1。

本记录确认原生成长、上限、通知去重与层数查询，并执行复生候选的资格检查至激活分支。**尚未确认完整的游戏内触发来源和初始层数，不据此更新词典，也不计入已解明词条数量。** `gameplayVerified` 为 `false`。

## 已执行验证

`tools/probe_revenant_fp_growth.py` 使用锁定哈希的 EXE、SpEffectParam 和 AttachEffectParam，在隔离环境中执行原生指令。结果保存在 `data/effect-revenant-fp-growth-partial-evidence.json`。

- `4CC320` 启用分支从本机角色的效果容器调用 `507910`，读取 state `2119` 对应行的原始 `+0x3CC` 字段，得到 `7500501`；随后执行原生 `3C7FD0` 发放和 `3DB410` 成长处理。
- `7500500` 根效果重复插入会去重。分别使用 0、1、3、6 份根效果，连续发出 36 次组件激活通知：无根效果不增长；有根效果时，每次通知推进一级，第 30 级封顶，多份根效果不加速增长。
- 成长容器始终只保留 `7500501…7500530` 中的一行。`6C91F0` 的实际 FP 上限结果与当前行 `maxMpRate` 一致，并非将 30 行倍率相乘。

| 成长级别 | FP 上限倍率（原始单精度值） |
| --- | --- |
| 1 | 1.0159578323364258 |
| 20 | 1.319154977798462 |
| 21 | 1.3372403383255005 |
| 30 | 1.500009536743164 |

这里的级别来自组件通知测试，**不能直接解释为游戏中的召唤次数**。已验证 `AttachEffectParam.permanentSpEffectId=7500501` 在所查调用者中充当层数查询的参考 ID，不是直接发放一级效果的指令。完整的装备／恢复语义尚未核实，不能默认角色从零级开始，也不能默认装备即获得一级。

## 同一对象的重复通知

实际执行 `3C7F10 → 4B3370 → 4CC320 → 507910 → 3C7FD0`。类型 `0x26` 的组件查询使用已存在组件的测试替身，未执行组件分配和注册。

`3C7F10` 检查接收对象的 `+0x1F9` 字节最高位；首次处理后设为 `0x80`，后续调用直接返回：

1. 对象 A 的首次启用通知增长一级。
2. 对象 A 再次启用不增长。
3. 对象 B 的首次启用再增长一级。
4. 对象 C 首次收到停用通知不增长，但仍设置该位；随后启用也不增长。

此标志的生命周期／重置入口尚未确认。测试没有清除该位来制造额外触发。组件发放的受益者来自 GameMan 的本机角色指针，不是通知接收对象；这不等于已验证联机归属。

## 根效果、保留与边界

- 将根节点的禁用标志设为 `0x800C0003` 后，`507910` 仍会返回成长效果，仍能增长。不能假设该 getter 会像通常的数值 getter 一样过滤禁用节点；真实装备资格尚需上游验证。
- 从原生容器删除根节点后，不再产生新成长；已经获得的成长行仍保留。这里是容器移除，不是完整的装备重建。
- 对已有成长分别推进 1、15、40、300 秒，未到期。参数中成长行的持续时间为 `-1`，saveCategory 为 `9`；未将它解释为跨远征或跨读档永久保留。
- 共 448 项检查：成长 144、对象去重 20、根存在／禁用／移除 3、保留 10、层数查询 127、复生判定 120、资格反例 15、复生重复通知 9。没有执行游戏客户端、实际召唤、当前 FP 写入或联机。

## 层数查询字段

实际执行 `E6E3D0 → E6E300 → 501F00`：前两个 getter 分别读取 AttachEffect 原始 `+0x40` 和 `+0x27`。当前行的值为 `7500501` 和 `1`。其中 `+0x27` 在现有 PARAMDEF 中被声明为 dummy 字节，JSON 解码结果未保留其含义，因此这里直接核对原始行。

模式 `1` 查询同一百位 ID 分组内、类别 `204` 的有效节点，返回最大的末两位级别。本组返回 `0…30`；无成长、仅根节点、其他成长分组和禁用的成长节点返回 `0`。有无根节点及重复根节点数量都不会把计数自动变为 `1`。

静态调用者 `824CB8`、`82A6FA`、`8FA2DD` 都把这两个 getter 的结果送入 `501F00`，再用于显示／条件分支。另一个 `BEB9A0` 调用者送入 `BEBA30` 的记录查询分支，尚未完整验证。以上证据证明了查询用途，不能据此排除所有其他内联读取，也不能代替完整的角色初始化测试。

## 复生候选至成长分派

从函数入口 `3930F0` 执行至成功 `393619`、请求拒绝 `3936B8` 或资格不符 `3937AE` 的边界：

- 本机角色虚函数 `+0x150` 条件须成立，目标 `+0x1F6` 的 bit 2 须置位，目标 NPC 行 `+0x26A` 的 bit 0 须置位。
- 原生位置差平方与 PlayerCommon 原始 `+0x16C=100` 的平方比较；测试中的距离恰为 `100` 可以通过，`100.01` 不通过。这是原生坐标值，未在词典中标注单位。
- 执行 `507AA0` 的原生效果查询；当前输入没有 state `2117` 的覆盖行，使用 PlayerCommon `+0x15C=35`。随机输入恰为 `35` 可以通过，`35.0001` 不通过。未模拟随机分布，不能把此检查当成实测触发率统计。
- `519EF0` 接受请求后，实际调用 `3C7F10(target, true)` 并执行成长链；拒绝请求则不增长。
- 空本机角色、角色条件不符、目标标志不符、NPC 标志不符、无匹配所有者且没有关联对象的反例均在随机判定之前退出。
- 同一目标的重复成功路径仍受 `+0x1F9` 标志去重，三次通知只产生一次成长发放。

场景位置、角色虚函数、合成 NPC 行的资格位、目标句柄、随机结果和世界请求接受结果是显式测试输入；对象登记、锁和句柄释放为替身。**未执行真实敌人生成／复生，也未验证具体 NPC 的资格。** 首轮“无匹配所有者”测试因合成目标缺少效果容器失败，补齐空容器后重新执行全部 448 项检查通过；没有把该测试构造错误解释为游戏限制。

静态调用者 `3DD517` 将当前对象送入 `3930F0`。其后的 state `453` 检查位于调用之后，不是本次复生判定的前置条件。
