# 打倒敌人时恢复周围我方人物的血量

7090100 每次触发为周围友方恢复 20 HP，范围半径参数为 15 米，不包括触发者。重复装备不增加单次恢复量或发射次数；连续击杀分别触发，不同角色分别触发的恢复量也相加。

[探针](../../tools/probe_team_kill_heal.py)与[证据](../../data/effect-team-kill-heal-evidence.json)固定当前 PC EXE、MMV regulation 和原始 PARAM。234 项原生检查覆盖装备、击杀分派、发射、命中后的接收、恢复包、重复通知及多来源组合。`gameplayVerified=false`，未运行完整场景或多人游戏。原始资料只读。

## 两种击杀分支都是 20 HP

实际装备选择 `4FEA30 → E6E150 → E6E3B0` 允许 11 种角色的 1／2／3 份装备，根效果为 7090100，类别 0、状态 199。实际插入后，同 ID 只保留一份。

奖励入口 `668380` 将本角色的效果容器与角色指针交给 `50A150`。后者按击杀分支标记选择 7090101 或 7090103。原生执行确认两条分支都生效；奖励金额为负、零、小数或正数的显式输入，也不会改变此处的分支选择。奖励写入和通知接收为记录器，未模拟真实敌人死亡及奖励归属。

这两个分支不能解释为“本人补刀／队友补刀”。已有击杀链研究将标记追到敌人 NpcParam `+0x26A` 的 bit 2（当前定义为 `enableSpKillId`），另有保存奖励的恢复路径。具体敌人名单与所有奖励来源不属于本批验证。

7090101、7090103 都是状态 275、类别 10、零寿命的发射效果，二者都请求 Behavior 990901000。该行为引用 Bullet 900901000；弹体攻击行为号也是 900901000，唯一恢复负载为 **7090102**，`changeHpPoint=-20`，`changeHpRate=0`。7090104 虽有恢复 7 HP 的参数，但不是这两个当前行为分支的弹体负载，因此不能把此词条写成“20／7 HP”。这不代表 7090104 在其他未查路径中一定不可达。

## 一次性恢复和独立触发

原生 `50AA20 → 397570 → 3975D0` 对每个击杀发放的标记请求一次弹体，`343280` 在瞬发请求下只创建一发。30／60／120 Hz、同帧／相邻帧／间隔 0.1 秒／间隔 1 秒的击杀通知都逐个发射；装备三份与一份的结果一致。

接收恢复行 7090102 为类别 10、寿命 0、周期参数 0.5。实际插入和 `5057D0 → 50ACD0 → 506EC0` 执行后，每个有效命中只产生一次 `[20, 0, 20, 0, 0, 0, 0]` 的 HP 恢复包。同帧收到两次为 40，邻接帧收到两次则分别为 20，之后不会继续恢复。这里的 0.5 秒不是玩家触发冷却，也不是持续回血间隔，页面不展示它。

两名独立来源的命中保留各自恢复量；最大 HP 为 1／99／1000／2345 时单次包仍为 20。“提升圣杯瓶恢复量”和降低圣杯瓶恢复量的受测修正不改变它。与普通“持续恢复血量”在 0／1／3 份组合中，三秒内逐帧的七通道恢复包等于两个独立来源相加。尚未执行最终当前 HP 的写入、上限及溢出处理。

## 目标与自身排除

攻击行 `selfTarget=0 / friendlyTarget=1 / opposeTarget=0`。实际接收检查 `43BE60 → 3C80A0 → 3DB410` 使用原生关系筛选；接收类型为 1 时，来源类型 1／2／4 接受，0／3／5／6／7／8／9 拒绝。这些是显式内部类型，不能据此命名所有 NPC。

直接强制投递自身命中也能通过接收检查，但它跳过了上游碰撞筛选，不能推断实际词条会治疗触发者。

本批继续执行 `535A60..535BF9` 的碰撞筛选信息构造。原生 `E6D630` 读取真实攻击参数，`535BD7` 检查 `+0x81` 的 bit 2，即 `selfTarget`。关闭时经 `536870` 取得来源类别，写入筛选字的高位；打开时不加这部分。在显式来源句柄 `0x10000001` 下，当前恢复攻击的筛选字为 67108961；自身目标开启的对照攻击 2 为 98。

这证明该参数参与更早的筛选信息构造，解释了为何不能只看接收函数判断自身效果。最终碰撞筛选消费者、真实空间搜寻和半径边界仍未执行，不将这三项构造检查称为完整场景的自身排除验证。
